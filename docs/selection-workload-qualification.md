# Step 2: workload qualification for cost-informed selection

The development workload now includes a verified necessary-work challenge alongside the existing A/B diagnostics. Six new cases reached independently verified goals. Both initial candidates capable of producing the required certificate incurred more CPU than an irrelevant fact from the same state. No cost estimator or modified selector has been implemented or evaluated.

This completes the bounded development-workload step of the [comparison protocol](cost-informed-selection-protocol.md). Held-out structural variants are reserved but not generated or evaluated here; they must be qualified and frozen before fitting. This is not yet a complete generalization benchmark.

## Why the earlier example needed a challenge

In the original A/B KB, selecting `ReadyB -> CertificateB1` can produce a certificate without first selecting ReadyB and generating every B certificate. Therefore the expensive ReadyB expansion is not necessary for a B proof. Removing such selectable implications would change the reasoner and manufacture a limitation.

The new family keeps all candidates and native rules available. It gives both members of the required modus-ponens pair additional applicable work:

```text
R = Ready(unit0, required)
C = Certificate(unit0, required)
L = (Implication R C)

Inputs: R, L, (Implication C Goal), four unrelated Idle facts

Additional inputs, for i = 1 ... width:
    (Implication R SideFact_i)
    (Implication L SideRule_i)

Required proof: R + L -> C; C + (Implication C Goal) -> Goal
```

`L` is itself a ground implication term. The existing native modus-ponens rule can use it as a premise for another implication; no new rule, sleep or synthetic duration is introduced. The side conclusions are terminal and cannot establish Goal. This construction deliberately loads the needed pair with additional symbolic work; it is a synthetic diagnostic, not a representative application dataset.

All inputs have strength 1, confidence 0.9 and distinct evidence IDs. Widths 4 and 16 give 15 and 39 input records. Each uses canonical order, an order swapping R/L, and a seeded shuffle (17). The unchanged acceptance criterion is strength 1, confidence at least 0.729, tolerance `1e-12`, with a replayable proof. Native caps remain 100 expansions and 4097 queue-limit arguments.

## Necessity argument and checks

For these exact fixtures, the only implication with Goal as consequent has C as antecedent; the only implication with C as consequent is L. Neither C nor Goal is supplied initially. There are no STV marginals or other link families activating the marginal-dependent syllogistic, inversion, evaluation or similarity rules. Native MP can generate only the terminal side terms, C and Goal; revision cannot introduce a previously absent term. No rule derives R or L. Consequently, a first C must be generated by expanding R or L against the other record in the belief buffer. Either operation is permitted; neither is removed or assigned a different confidence.

This reasoning is scoped to the closed ground fixture and inspected pinned rules. The shape validator rejects additional shortcuts, marginals, duplicate records or changed evidence instead of applying the argument to an altered KB.

Verification included:

- Six **authored** two-MP witnesses, replayed independently; these establish the intended derivations, not native discovery.
- Six unmodified native runs and six state/proof-traced counterparts with unchanged original output and selection sequence.
- Six **captured native first-answer certificates**, independently replayed against input licensing, formulas and evidence guards. All had strength 1, confidence approximately 0.729 and evidence `[1, 2, 3]`.
- Every initial candidate at both canonical widths was expanded using the existing helper and independently compared with the native one-step loop: **54 candidate comparisons** with identical ordered output queues. Only IDs 1 and 2 generated C. Each generated `width + 1` results; the chosen Idle fact generated none. Other selectable side implications remained available and generated one side result each.
- Four negative native controls removed R or L, one at a time, at both widths. None returned Goal. These change the KB and are logical controls only, not cost comparisons; bounded runs alone would not prove universal unreachability.
- No trimming in the six positive native runs. Three added tests check valid authored proofs and rejection of shortcuts, extra marginals and altered evidence. The full **79-test suite passed**.

| Width | Canonical first proof | Swapped first proof | Shuffled first proof | Full native expansions per ordering |
| --- | ---: | ---: | ---: | ---: |
| 4 | 3 | 3 | 9 | 25 |
| 16 | 3 | 3 | 58 | 73 |

These are expansion counts, not CPU speedups. They underline that queue order and which statement triggers an inference matter even with a common proof objective.

## Initial-state CPU qualification

Each necessary endpoint was paired with the same irrelevant fact from the same canonical initial state. Six fresh-process blocks per contrast used 20 warm-up pairs, 10 measured pairs in balanced randomized order, and 30 empty-harness samples. There were **240 measured pairs / 480 timed expansions** across four contrasts.

The previously validated thin adapter calls the mechanically extracted native expansion. Original immutable inputs are reused before every sample. Timing begins after callable/input preparation and candidate selection and ends after inference, result collection and queue updates. Output verification, printing and preparation are outside this local window. This is local CPU qualification, not a complete online selector or query measurement.

The saved configuration, written before running, required every block to have empty-harness p95 no greater than 10% of its faster-candidate median, a paired median ratio above 1.2, and a paired median gap above five times the largest block empty-harness median. All four contrasts passed. These are descriptive pilot gates, not the earlier Step 6 multiplicity-adjusted statistical analysis.

| Width | Necessary candidate | Idle CPU, microseconds | Necessary CPU, microseconds | Paired cost ratio | Maximum empty p95 fraction |
| --- | --- | ---: | ---: | ---: | ---: |
| 4 | R | 88.10 | 194.71 | 2.17 | 5.49% |
| 4 | L: R -> C | 91.54 | 222.22 | 2.36 | 6.93% |
| 16 | R | 192.32 | 912.32 | 4.67 | 4.10% |
| 16 | L: R -> C | 201.34 | 997.71 | 4.90 | 4.14% |

CPU columns are medians of block medians. Ratios are medians of within-block paired ratios; they need not equal the quotient of those CPU columns. Each row has its own process blocks, explaining the different Idle measurements at the same width. No samples were replaced or excluded.

**Limit:** necessity is a structural statement; the cost contrast is measured only in the initial state. Selecting side rules first can change queues, beliefs, deduplication and subsequent costs. We have not established a lower bound on the CPU of every possible successful continuation. Step 3 must sample relevant later states before using an estimator to make decisions there.

## Workload groups retained and unresolved

| Group | Evidence and disposition |
| --- | --- |
| Original unequal-cost alternatives | Retain all nine A/B cases and the completed Step 6 findings. No new policy result is inferred. |
| Similar-cost control | The original width-1 swapped-input Ready comparison passed the relative-equivalence band (B/A 0.9996, reported interval 0.9956–1.0037). This applies to that pair/state, not all candidate costs. |
| Other width-1 controls | Canonical and shuffled initial comparisons remain instrumentation-unresolved; do not relabel their similar point estimates as established equivalence. Retain them. |
| Necessary-work challenge | Six new valid cases; both required endpoints costlier than Idle in the canonical initial-state pilot. No measured policy harm yet. |
| Held-out structural evaluation | Reserved shared-side-sink and disconnected-module variants, not timed or trained on. Exact instances and validity must be frozen before model fitting. |

The challenge can expose a preference for cheap but unproductive work. It does not prove that a cost-informed policy will fail: it may still order the remaining work favorably, and prediction overhead may dominate either way. A benefit-aware learned policy is not part of this step. The benchmark still tests derivation validity, not empirical probability accuracy.
