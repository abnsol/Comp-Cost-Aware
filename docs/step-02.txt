What was inspected

Instrumentation
src/pln_cost/tracing.py generates a copy of the exact pinned library with THREE
print-only insertions at successful result constructors: binary left/right,
binary right/left, and unary. Each logs ordered parent Sentence records and the
new Sentence, then returns the original result expression. The rule definitions,
priority selection, evidence guards and queues are not edited.
The external repository is unchanged. The generated library, upstream MIT license
and a unified instrumentation diff are retained in each result directory.
The ground-only parser and first-witness extraction are scoped to this fixture;
they are not advertised as handling arbitrary variable-bearing PLN programs.

Independent replay scope
Certificate: four original input records plus two deductions plus one revision.
Only ancestors of the ACTUAL returned answer are replayed. Input identities bind
the exact term, truth value and evidence. Source commit/hash, fixture hash, query
and marginals are checked against the externally supplied contract. A proof must
be acyclic and every input authorized. The checker rejects unsupported rules.
Rule labels are independently recognized from captured parents, conclusion and
formula, not read from an unverified native rule-name annotation. The returned
proof in this case uses only the two supported rule families.

The native search also uses other rules; full logs contain592 binary result events
and100 unary result events, including duplicates. Those692 events are CAPTURED,
not692 independently verified transitions. Full queue evolution, choice optimality,
all intermediate results and statistical independence are not certified here.

Research interpretation
The world target is0.74. Native PLN ALREADY produced that estimate before revising
it toward0.688. This particular final forecast error is therefore not evidence
that CPU scarcity prevented finding an accurate candidate. It involves the
declared approximation stress case, revision and confidence-based output selection.
Correct execution of the pinned rules is distinct from a calibrated/accurate
probability. This result validates a debugging/evaluation example, not the claim
that adding computation-cost information improves PLN. Do not repurpose it as
evidence of a resource-allocation failure without a suitable controlled workload.

No CPU timing or estimator was added. Trace overhead is not measured and will
need fair accounting in any later budgeted comparison. No paper method has been
implemented. We will review the papers before choosing a cost-aware adaptation.
