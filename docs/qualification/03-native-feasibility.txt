2026-10-04. Completed; stop for user review before state-capture implementation.

Outcome
All nine cases returned a qualifying answer in actual pinned PLN. For each case,
an unmodified-library run and a separate print-only traced-library run completed
cleanly under the reviewed limits. All original output lines, including the full
ordered SELECTED sequence, were identical within each native/traced pair.
All nine returned answers have independently replayed native proof certificates.

Every returned answer:
  strength 1.0; confidence 0.8432620011567381.
Every captured answer proof:
  six input assertions, four ground modus-ponens applications, one revision;
  eleven nodes total. Two two-step paths give strength 1 and confidence
  0.7290000000000001 each, then disjoint A/B evidence permits revision.
  For equal input confidence c, revised confidence is 2c/(1+c), approximately
  0.843262. Strength remains 1. This higher PLN confidence is not evidence of
  improved empirical probability accuracy or an effect of computational cost.

Scope of what is established
These specified cases are solvable by this particular pinned PLN configuration.
The evidence is execution plus independent rule/evidence replay, rather than
merely the static witnesses authored in step two. Observed tracing parity holds
for these nine pairs; it is not a general proof that instrumentation is harmless.
Only returned-answer ancestor proofs are checked. No new rule family beyond
the already supported MP/revision subset was needed for those proofs.

Not established
- An actual expansion CPU-cost gap or a performance benefit from cost information.
- Time to the first qualifying answer in a committed belief state.
- Queue occupancy or whether trimming occurred; state instrumentation is pending.
- Generalization beyond this development KB family or probabilistic calibration.
Selection counts and generated-event counts are not CPU measurements. Logging
overhead is not a measured treatment effect. The 60-second wall timeout is a
safety bound, not a calibrated CPU budget. Offline replay costs are not latency.

Implementation and saved evidence
scripts/validate_qualification.py
  Reads the immutable step-two batch snapshot, verifies every fixture hash and
  rendered input against its configuration before execution, pins source/runtime,
  and runs the full native library without selector/rule changes. Saves failures
  independently and continues remaining cases. Refuses overwriting a run ID.
src/pln_cost/feasibility.py
  Parses QUALIFICATION_RESULT with this KB's evidence IDs. An explicit empty
  result is unanswered; missing/malformed results are validation failures.
  Compares every original line after removing only the existing trace markers.
tests/test_feasibility.py
  Rejects malformed/duplicate results, undeclared evidence and reordered original
  output. Replays all nine saved native certificates and verifies fixture/log
  hashes. Existing diagnostic parser and runtime interface remain unchanged.
